## Phase mapping

### Phase 0: Address Copilot review findings (0.5 day)

Do **before** starting v5.0 Phase 1a research, so the codebase is clean before adding new features.

#### 0.1 — Unclosed fenced code blocks → code to EOF

**Why:** Unclosed fences currently cause the rest of the document to be reflowed into paragraphs, which is surprising and breaks exporters.

**Plan:**
- File: `mdutil/parser.py` `extract_code_block()` (line 228+)
- Add a final `if no closing fence found:` block that returns the content from the opening fence to `EOF` with `end_pos = len(lines)`
- Add regression test: `test_parser.py::test_code_fence_unclosed_eof`
- Verify with a real export through PDF and HTML

**Test plan:**
```python
def test_code_fence_unclosed_eof():
    md = "```python\nprint('hello'\n\nparagraph after\n"
    tokens = parse_markdown(md)
    code_tokens = [t for t in tokens if t["type"] == "code"]
    assert len(code_tokens) == 1
    assert "paragraph after" in code_tokens[0]["content"]
```

#### 0.2 — Deduplicate parsing logic in `parse_markdown`

**Why:** The review identified repeated block-detection branches. Consolidate into a single pass.

**Plan:**
- Audit the two "identical" code-block/heading/hr/table/blockquote/list sections in `parse_markdown`
- Refactor to a single block-detection loop with helper functions (`_detect_block_type`, `_handle_heading`, etc.)
- Run existing 389 tests to verify no regression
- Add targeted tests for block-type detection ordering (e.g., code fence vs heading at same line)

**Scope:** Pure refactor — no behavior change. Run tests before/after to confirm.

#### 0.3 — CLI mermaid flag oddity

**Why:** `--mermaid` with `default=True` + `store_false` on `--no-mermaid` is functional but slightly odd.

**Plan:**
- File: `mdutil/cli.py` `build_arg_parser`
- Set `--mermaid` default to `True` (existing), make `--no-mermaid` the toggle with `action="store_false", dest="mermaid"`
- Or: set `--mermaid` default `False`, and add `--enable-mermaid` with `store_true`
- Simplest fix: keep `--mermaid` as `store_false` only (no separate `--mermaid` flag), default via config
- Add a small test in `test_cli.py`

#### 0.4 — Config type coercion validation

**Why:** INI files return strings; `_resolve_runtime_options` casts directly without validation.

**Plan:**
- File: `mdutil/config.py` and `mdutil/cli.py` `_resolve_runtime_options`
- Add explicit `int()`/`bool()` conversion helpers with helpful error messages on type mismatch
- Add test: config file with `mermaid = "yes"` (string) should coerce correctly

#### 0.5 — Exporter error granularity / debug logging

**Why:** Exporters swallow exceptions with terse messages; debugging is hard.

**Plan:**
- Add `--debug` flag to CLI (or use existing `--quiet` inversely)
- In exporters: replace bare `print(...)` with `logger.debug()` / `logger.error()` using Python `logging`
- `--debug` sets `logging.getLogger("mdutil.export").setLevel(logging.DEBUG)`
- Verify exporters still produce clean output in normal mode

#### 0.6 — README fixes

**Why:** Clone URL points to `your-username`, story section is long.

**Plan:**
- File: `README.md`
- Update clone URL to `https://github.com/jhenkins/mdutil.git` (or current canonical URL)
- Mark story section as "Background" with a collapsible-style note or shorten it
